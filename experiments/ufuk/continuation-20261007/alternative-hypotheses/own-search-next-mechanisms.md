# Two CPU-feasible own-search follow-ups

Scope: prospective diagnosis only. The active own-Q producer and current run are frozen. This note recommends no launch or change to an already registered run. No searches, fits, or matches were run for this note.

## What the recorded failures say

The immediate concern is target quality and target-policy coupling, not missing optimizer machinery. The independent 2,048-root own-Q audit reproduced 8,388,608 total nodes per seed but its completed-depth counts were shallow: seed 20262905 had 51 depth-2, 638 depth-3, 291 depth-4, 40 depth-5, and 4 depth-6 searches; seed 20262906 had 51, 611, 307, 48, and 7. Most labels are therefore a shallow search's estimate from the same frozen model that generated the games, not an independent stronger opponent signal. This is an inference from the depth histogram, not proof that depth caused the losses.

The full-head, scalar-search, and own-MC fits all passed their native-resume checks but missed every frozen two-seed known-book screen gate. Candidate-versus-SF512 scores were MC `.03125/.0625`, SC `.03125/0`, and full critic `.03125/0`; direct candidate-versus-E8 scores were MC `.53125/.5625`, SC `.50/.59375`, and full critic `.71875/.53125`. No candidate reached `.25` versus SF512 or the required SF gain. These 16-pair-per-seed development screens are not virgin confirmation. Receipts: `experiments/ufuk/cpu-fresh-learning-arena-v1/actual-result/ROOT-audit-v3-result.json` and `.../independent-review-result.json`. The old C18 fits were only profile/latency checks, not strength evidence.

The current collector supplies one best-move root value per pre-action position, no action-distribution target, and separately marks completed-game WDL versus UNKNOWN caps. It freezes one parent for both players. Thus plain MSE to its root values can only copy that parent's shallow search; terminal-only MC throws away usable value information at unknown tails. Neither is policy improvement by itself.

## Candidate 1: trajectory TDLeaf(lambda) targets

**Mechanism.** Form a single per-position scalar target by backing up the same frozen-parent search values through the actual played trajectory and mixing them with exact own terminal result using fixed `lambda=0.5`. Convert each `q_mover` to White POV (`q` when White moves, `-q` when Black moves) before recursion; convert the final target back to the model's required POV. This avoids alternating-mover sign mistakes. For a completed episode, the final action has an exact W/D/L return; recursively blend each earlier row's next-state search value with its later return. For an open cap or row-budget tail, the last *recorded pre-action* Q is the endpoint bootstrap for earlier rows, and that last row itself keeps its own Q target. There is no value call on the unrecorded post-action final board. Never turn UNKNOWN into a draw. Keep the frozen-parent anchor and same update/optimizer budget. This is a path-consistency target: unlike the previous `.5 MC + .5 search-Q` objective, the two signals combine along the actual trajectory before each row's target is made.

**Why it may help / why it may fail.** It propagates terminal corrections backward through earlier states while retaining search labels for open games, at essentially zero extra search cost. It may still inherit the parent's errors and amplify a bad line; exact outcomes are conditioned on games the weak parent chooses to finish. The current full-critic mixed-loss failure is important negative evidence, so TD(lambda) is a specific algorithmic ablation, not a promised fix.

**Controlled comparison.** Reuse one fixed-parent collection per seed and exact row IDs. Q-only and lambda arms use the same all-row mask; the MC-only reference uses only rows from completed games, with its known-row count and game-balanced sample schedule frozen from the sealed data receipt before any candidate fit. Fix optimizer steps and total sampled rows per arm in advance; if the completed-game count falls below the preregistered floor, mark the MC comparison unavailable rather than silently oversampling it. Keep cap rows as Q-bootstrap targets in Q/lambda arms and out of the MC loss. Freeze all choices before candidate games. Preserve both E8 and own-parent comparisons and every original gate on two fresh registered seeds. Do not tune lambda on the screen.

**Prior art.** TDLeaf(lambda) was designed to combine TD learning with game-tree search in chess; this exact family is established, not novel. AlphaZero trains from self-play terminal outcomes and search-improved targets. MuZero uses bootstrapped n-step value targets and its Reanalyze variant recomputes search targets on replayed positions. The distinction here is only a small CPU implementation over the existing scalar own-Q stream, not a new RL method.

## Candidate 2: equal-node disagreement-adaptive own-search reanalysis

**Mechanism.** On the same 1,024 fixed TRAIN histories, first run the frozen parent at 2,048 nodes everywhere. Compute a predeclared search-disagreement score `abs(Q_2048 - V_static(root))`; rank by score then stable row ID. Rerun exactly the top 192 histories from the full root/history at 32,768 nodes. Use the 32,768 value on those 192 rows and the 2,048 value on the others. One adaptive-target job costs `1,024*2,048 + 192*32,768 = 8,388,608` nodes per seed. It is not compute-matched to the original actor collection alone: to compare fairly after a fixed 8,192-node actor collection, run a second, *equal-cost* reanalysis job for the control, using 8,192 nodes on all 1,024 histories. Thus each training arm receives the same frozen self-play data and spends the same additional 8.39M reanalysis nodes; only target-generation allocation differs. `V_static` is the frozen parent evaluated once at the root. No terminal/game outcome enters selection. Both arms then train the same model with identical MC targets, anchor, updates, and evaluation gates.

**Why it may help / why it may fail.** It asks whether the uniform 8,192 budget is wasted on positions where the partial search agrees with the static parent, while a fixed portion of the budget could produce more decisive labels on high-disagreement positions. Its disagreement measure is only a heuristic, not calibrated uncertainty; it may allocate extra work to positions that are simply tactical/noisy, and the reduced-budget 832 rows may become worse targets. Record depth, node, and evaluation histograms for selected/nonselected roots. Reject if it does not beat the fixed-8,192 arm under the original gates.

**Control and limits.** Freeze the ranking rule, 192-row count, root ordering, and tie-break before labels are read. Same parent weights and same self-play trajectories, exact total node budget, same trainer/update count, and original strength gates. The 32,768 search must replay complete root histories and preserve claim-draw/repetition handling. Do not call the score “uncertainty” in reports unless independently calibrated against search instability.

**Prior art.** Variable search effort and reanalysis are established. KataGo's playout-cap randomization varies search budgets to improve training coverage; MuZero Reanalyze revisits past states with current search; work on targeted AlphaZero search control studies how to spend search for policy improvement. This proposal is a constrained budget-allocation ablation on this engine, not a novelty claim.

## Priority and no-go conditions

Run candidate 1 first if enough completed trajectories exist: it reuses the current data and adds essentially no search cost. Candidate 2 is the more direct response to the shallow d2–4 histogram, but only if both arms can be collected under the same frozen-parent and node budget without delaying the primary gate. Do not combine the two into one treatment. Neither can replace the original E8 primary comparison, the parent comparison, two-seed requirements, or unchanged final gates. A world model is not justified by these records: chess rules already provide exact transitions, while a learned model would add CPU cost and model error without addressing the measured bottleneck more directly.

## Primary literature

- Baxter, Tridgell & Weaver, [TDLeaf(lambda): Combining Temporal Difference Learning with Game-Tree Search](https://arxiv.org/abs/cs/9901001), chess evaluation learning with search-aware temporal differences.
- Silver et al., [Mastering Chess and Shogi by Self-Play with a General Reinforcement Learning Algorithm](https://arxiv.org/abs/1712.01815), search-improved self-play targets and terminal outcomes.
- Schrittwieser et al., [Mastering Atari, Go, Chess and Shogi by Planning with a Learned Model](https://arxiv.org/abs/1911.08265), n-step bootstrapped targets and MuZero Reanalyze.
- Wu, [Accelerating Self-Play Learning in Go](https://arxiv.org/abs/1902.10565), including playout-cap randomization and target design.
- Trudeau & Bowling, [Targeted Search Control in AlphaZero for Effective Policy Improvement](https://arxiv.org/abs/2302.12359), search allocation as part of the policy-improvement operator.
- Danihelka et al., [Policy Improvement by Planning with Gumbel](https://openreview.net/forum?id=bERaNdoegnO), relevant to low-simulation policy improvement; current HarbiChess value-only search does not implement this policy-head setup.
