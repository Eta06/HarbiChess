# ESAS parent-relative FPU allocation preregistration (2026-08-28)

## Hypothesis

With the collapsed release value head, zero-valued unvisited children look as
good as visited children. At 64 simulations the baseline opens nearly every one
of roughly 26 legal root actions. Parent-relative first-play urgency (FPU)
reduction should concentrate low-budget search without changing backup,
terminal values, policy targets, or the network.

Lc0 uses parent Q minus a reduction scaled by the square root of visited policy;
KataGo exposes separate default-like maxima of 0.1 at root and 0.2 in the tree.
Those constants are fixed here before results.

## Frozen change

- Existing zero-FPU behavior remains the default (`0.0`, `0.0`).
- Treatment: root reduction `0.1`, interior reduction `0.2`.
- For an unvisited child:
  `FPU = parent_mean_value - reduction * sqrt(sum(visited_child_priors))`.
- Visited-child Q, PUCT exploration, terminal values, sign propagation,
  deterministic ties, batching, and rules are unchanged.

## Frozen qualification

Rerun the complete ESAS system-teacher experiment with the same release model,
seed, 32 opening pairs, 64 games per arm, 8-ply openings, 256-ply cap,
64/128/256 budgets, tactical suite, workers, and original gates. The zero-FPU
raw control is regenerated by the same program; no earlier game is substituted.

Additional equivalence tests must prove:

1. explicit zero reductions reproduce legacy search results exactly;
2. FPU never changes legal support, terminal resolution, value perspective, or
   backup signs;
3. deterministic searches remain repeatable.

No threshold or sample size changes. Passing authorizes only larger fresh replay
design and persisted learner/latest implementation. Failure keeps generation
blocked and moves the next search-allocation experiment to Full Gumbel MuZero,
not FPU constant tuning.
